# Nommer un agent

```
Prénom (fonction)
```

## Les règles

- **Un prénom**, deux syllabes de préférence. Court : il sera prononcé souvent.
- **La fonction en un seul mot français**, au singulier, entre parenthèses.
  Pas de titre à rallonge : « (architecte) », pas « (responsable architecture) ».
- **Le fichier prend le prénom seul, en minuscules** : `.claude/agents/leo.md`.
  La fonction vit dans le nom affiché et dans sa fiche.
- **Unique dans le projet.** Deux Léo et on ne sait plus lequel a raté.
- **Jamais le prénom d'une personne réelle du projet** — ni toi, ni un client,
  ni un collègue. On dit « Nora est passée à côté d'une régression » ; ça ne doit
  désigner personne.
- **Le nom se fixe au recrutement.** Renommer plus tard casse les références.

## Pourquoi un prénom plutôt qu'un identifiant

Un agent nommé `code-reviewer-v2` ne se reproche rien, et on ne lui apprend rien :
c'est un outil, on le remplace. Un agent nommé Nora a un dossier, des erreurs, des
progrès. **Le nom est ce qui rend la formation naturelle** — et la formation est
tout l'intérêt du système.

## Un poste, un agent

Avant d'en nommer un nouveau : **est-ce qu'un agent en poste fait déjà ça ?**
Deux agents qui se recouvrent, c'est le mauvais qu'on appelle — exactement le
problème qu'on corrige sur les skills. Si le besoin est proche, on étoffe le
dossier de celui qui est là.
